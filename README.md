# KADR · Кинотеатр — практическая работа №5

**Лабораторная работа №7.** В отладочной сборке откройте «Лабораторная работа №7» на экране входа или в кабинете. Команды запуска тестов, локального HTTP-сервера и снятия доказательств собраны в [инструкции к работе №7](docs/Lab7.md). Для старого тестового раннера используется параметр `-PlegacySmoke`, который передают скрипты `tests/device.ps1` и `tests/database.ps1`.

Полностью локальное Android-приложение на Java с настоящей SQLite БД. Папка проекта, Gradle Wrapper 9.3.0, Android Gradle Plugin 8.7.3 и SDK 35 сохранены. Новые библиотеки приложению не нужны. Oracle можно оставить выключенным.

## Быстрый запуск

Откройте эту папку в Android Studio, выберите `app` и нажмите Run. Либо установите `output/KADR.apk` на Android 7.0+.

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | admin | Admin123! |
| Пользователь | viewer | Cinema123! |

Кнопки демо-доступа на экране входа заполняют поля; затем нажмите «Войти». Новых пользователей регистрирует администратор. Самостоятельной публичной регистрации нет согласно заданию.

## Что работает

- Вход, сохранение сессии на 30 дней, выход с отзывом токена, личный кабинет, изменение имени/контактов и пароля.
- Две роли. Администратор регистрирует пользователей, меняет роли, отключает/включает аккаунты и сбрасывает пароли. Последнего активного администратора нельзя отключить или понизить.
- Главный экран показывает «Здравствуйте, {имя}», «Личный кабинет», «Выйти» и только администратору — «Регистрация пользователей».
- Афиша: поиск по названию, жанру и режиссёру, фильтры жанра/формата, сортировка по названию/рейтингу/новизне, выбор любой даты.
- Описание фильма, оригинальная векторная афиша, сеансы, язык, формат, возраст, рейтинг и отзывы. Один отзыв на пользователя/фильм; его можно обновить или удалить. Администратор может модерировать отзывы.
- Избранное хранится отдельно для каждого пользователя.
- Схема зала, свободные/занятые/выбранные места, до 6 мест в одной брони, расчёт стоимости, промокоды.
- Атомарное бронирование: UNIQUE(show_id, row_no, seat_no) и SQLite-транзакция исключают двойную продажу. Ошибка откатывает всю бронь.
- Электронный билет: уникальный код и настоящий QR, история, поиск/фильтры, отмена до начала сеанса с освобождением мест.
- Сохранение билета в PNG через системный выбор файла, передача деталей через меню «Поделиться», экспорт ICS с напоминанием за час для календаря.
- Касса: администратор находит код в «Бронирования и касса», отмечает полученную оплату, проверяет и гасит оплаченный билет. Вход открыт за час до сеанса; повторное использование запрещено.
- Администратор добавляет/редактирует фильмы, залы, сеансы, цены, языки, форматы и промокоды. Архивирование сохраняет историю; активные будущие сеансы сначала нужно отменить.
- Расписание проверяет пересечения сеансов в одном зале с учётом 20 минут уборки. Сеанс с действующими бронями защищён от изменения. Отмена всего сеанса отменяет брони и освобождает места.
- Панель администратора показывает количество активных пользователей, будущих сеансов, действующих броней и сумму оплат в кассе.

## Границы проекта

SQLite хранится на телефоне/эмуляторе в приватном каталоге приложения (`databases/kadr_cinema.db`). Два аккаунта на одном устройстве используют одну БД; между разными телефонами синхронизации нет. Оплата производится в физической кассе; приложение регистрирует её получение. Банковский эквайринг, облачная синхронизация и отправка SMS/email не подключены. ICS-напоминание обрабатывает календарь, в который пользователь импортирует файл. Oracle и сервер не требуются.

При первом запуске создаются 6 демонстрационных фильмов, 3 зала, расписание на ближайшие 8 дней и промокоды FIRST (10%) и STUDENT (15%). Каталог вымышленный, афиши нарисованы векторно. Данные создаются один раз и после этого управляются администратором. Для полного сброса используйте системную очистку данных приложения; она удаляет все аккаунты и бронирования.

## Сборка и проверки

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat assembleDebug assembleDebugAndroidTest --offline --no-daemon --max-workers=2
.\tests\run.ps1
.\tests\device.ps1
```

Для последней команды должен быть запущен эмулятор или подключён Android с USB-отладкой. Инструментальные тесты проверяют БД в отдельном файле `cinema-verification.db`, а затем открывают реальные экраны и сохраняют изображения в `output/screenshots`. Диагностическая бронь для снимка билета отменяется после проверки.

Исходный APK: `app/build/outputs/apk/debug/app-debug.apk`. Готовая копия: `output/KADR.apk`.

Android lint запускается командой `.\gradlew.bat lintDebug`; первый запуск требует загрузки компонентов lint, если их нет в кэше. Он не переустанавливает Gradle.

## Код и БД

| Файл | Назначение |
|---|---|
| CinemaActivity.java | Экраны, навигация, формы, выбор мест, экспорт |
| CinemaDb.java | Схема SQLite, начальные данные, репозиторий, проверки ролей, транзакции |
| CinemaRules.java | Валидация, хеширование паролей, цены, даты |
| FilmArt.java | Оригинальные векторные афиши |
| TicketQr.java | QR версии 1, коррекция L, проверен независимым кодировщиком |
| TicketImage.java | PNG билета с адаптивной высотой |
| CalendarFile.java | UTC-события ICS, экранирование, перенос строк UTF-8 |
| CinemaSmokeTest.java | Проверки БД, конкурентного доступа, ролей и UI на Android |

Java-код находится в `app/src/main/java/com/example/kaspikids`. Идентификатор пакета сохранён, чтобы использовать существующую конфигурацию Android Studio. Название приложения и проекта — KADR.

Таблицы: users, sessions, movies, halls, shows, bookings, booking_seats, favorites, reviews, promos. Внешние ключи включены. Пароли хранятся как PBKDF2-HMAC-SHA1 (120 000 итераций, 256 бит) с индивидуальной случайной солью; токены сессий в БД хешируются SHA-256. В приватных настройках хранится только токен, а не пароль. Защищённые операции повторно проверяют роль в репозитории.

Схему и данные можно посмотреть через Android Studio → App Inspection → Database Inspector при запущенном приложении (Android 8+), либо через Device Explorer → data/data/com.example.kaspikids/databases.

Отчёт, схема БД и инструкция для демонстрации находятся в `docs`.

## Встроенный просмотр базы данных

В нижнем меню откройте «База». ER-диаграмма строится из действующей SQLite: 10 таблиц, 66 столбцов и 11 внешних ключей. Доступны перемещение, масштабирование двумя пальцами и кнопками, поиск таблицы/столбца, переход к выбранной таблице и открытие её схемы нажатием.

Вкладка «Таблицы» показывает типы, первичные и внешние ключи, ограничения NULL, индексы и CREATE TABLE. Администратор также видит записи: поиск по значениям, сортировку, страницы по 50 строк, подробности строки и экспорт текущей страницы в CSV. Хеши паролей, соли и токены скрыты. Обычный пользователь видит структуру; доступ к записям проверяется и в интерфейсе, и в репозитории.

«Проверки» запускает проверку целостности SQLite и внешних ключей. SQL-экспорт сохраняет только структуру через системный выбор файла. Раздел работает на чтение; изменения данных выполняются через остальные экраны KADR. Oracle не требуется. Проверка нового раздела: `tests/database.ps1` при работающем эмуляторе. Подробности: `docs/DatabaseExplorer.md`.
