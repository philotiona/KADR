# Версионирование KADR (SemVer)

`versionName = MAJOR.MINOR.PATCH`, задаётся тремя переменными в `app/build.gradle`.

| Часть | Когда повышается | Пример |
|---|---|---|
| MAJOR | Несовместимые изменения: новая схема БД без миграции, удаление функций, повышение minSdk, смена способа входа | 1.4.2 → 2.0.0 |
| MINOR | Новая функция без поломки старых данных и сценариев | 1.0.0 → 1.1.0 |
| PATCH | Только исправление ошибок (в т.ч. hotfix) | 1.2.0 → 1.2.1 |

При повышении MINOR сбрасывается PATCH, при повышении MAJOR — MINOR и PATCH.
Суффиксы `-debug` и `-staging` добавляются автоматически (`versionNameSuffix`) и в магазин не попадают.

## versionCode

`versionCode = MAJOR * 10000 + MINOR * 100 + PATCH`

| versionName | versionCode |
|---|---|
| 0.1.0 | 100 |
| 1.0.0 | 10000 |
| 1.1.0 | 10100 |
| 1.2.0 | 10200 |
| 1.2.1 | 10201 |

Правила:
1. versionCode только растёт: магазин отклоняет загрузку с кодом, который меньше или равен уже загруженному (в любом треке).
2. Каждая загруженная сборка получает новый код, даже если она не вышла в production.
3. MINOR и PATCH не превышают 99.
4. Тег Git `vX.Y.Z` должен совпадать с versionName — CD-конвейер проверяет это до сборки.

## Git-теги

```bash
git tag -a v0.1.0 -m "KADR 0.1.0 - first internal build"
git tag -a v1.0.0 -m "KADR 1.0.0 - first public release"
git push origin --tags
```
